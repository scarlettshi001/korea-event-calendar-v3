## 🔥 值得做目的地运营：可解释评分

当前不调用付费 AI API，先用可解释规则自动打分。达到 4 分即标记为“🔥 值得做”。

加分信号包括：

- 中国直飞城市：+2
- 明显追星 / 音乐节 / 世界巡演信号：+2
- 普通演出事件：+1
- 活动持续 ≥2 天：+1
- 国际 / 大型节庆关键词：+1
- 来自主流票务平台：+1
- 美食 / 季节旅行场景：+1
- 本轮新发现：+1

每张活动卡会直接显示判断理由，而不是只给一个黑盒分数。

### 中国直飞配置

配置位于 `data/city_access.json`。航线存在航季变化，因此这里设计为**可维护配置**，而不是把航线判断写死在代码逻辑中。后续可再接“新开航线监测”自动维护。

### Instagram 自动发现

对于上述文化财团，脚本会扫描官网里的官方 `instagram.com` 链接，并自动加入本轮监测。Instagram 可能要求登录或采用动态渲染，所以全部采用 **soft-fail**：抓不到不会影响其他源。

同理，韩国旅游发展局小红书也采用 soft-fail。只有帖子出现**明确城市 + 明确活动日期 + 活动信号**时才写入日历，避免普通种草帖误报。

## 自动更新

`.github/workflows/update-events.yml` 已设置每两天执行：

```bash
npm install
npm run update
```

如果某个平台登录、验证码或反爬导致失败，脚本会记录失败，但继续抓其他来源。

## 本地预览

```bash
npm install
npm run dev
```

## 发布 GitHub Pages

1. 上传整个项目到 GitHub。
2. Settings → Pages。
3. Source 选择 `Deploy from a branch`。
4. Branch 选择 `main`，目录 `/ (root)`。
5. 保留 `.github/workflows/update-events.yml`，让自动更新持续运行。

## v4 分类规则（前台统一中文名称）

活动前台只使用以下 4 类：

1. **特色盛典**：大型音乐节、电影节、双年展、艺术节、国际/世界级节庆、博览会等。
2. **追星人狂喜**：韩国乐队、男团女团、演员/明星，以及外国艺人在韩国举办的演唱会、巡演、粉丝见面会、Fancon、Showcase 等。
3. **特色活动**：地方烟花、无人机表演、美食节、夜市、市集、快闪、花季/枫叶、地方展览、体育/城市活动等。
4. **购物狂欢**：Olive Young（O.Y SALE / 올영세일）、免税店、百货/商场、品牌折扣季与大型购物促销。

### 中文活动名

- `title` / `titleZh`：前台显示中文名。
- `titleOriginal`：保留来源网站上的韩文/英文原名，用于人工核对。
- 新抓取活动优先使用中文词典规则转换；仍含韩文时，会尝试无 Key 的机器翻译接口；翻译失败时自动回退为中文类型名，不会让韩文活动名直接成为主标题。

## v5：覆盖率修复（2026-09-09）

上一版只抓“票务平台总站/区域入口”，会严重漏掉动态页面里的演出。v5 改为：

1. **按城市主动搜索** NOL Ticket + Melon Ticket：釜山、大邱、光州、大田、蔚山、清州、水原、全州、庆州、昌原、浦项、丽水、江陵、春川、天安、世宗、金海。
2. 新增 **BIFF 官方站专用解析器**：直接抓釜山国际电影节及 Actors’ House。
3. **Ticketlink 开票公告递归抓取**：从公告列表继续打开详情页，而不是只看首页。
4. 新增 `data/verified_events.json`：把官方/票务已确认的高价值事件作为“核验底稿”，自动抓取失败时也不会把核心事件从日历里删掉；活动结束 30 天后自动淘汰。
5. 票务日期解析支持 `2026.9.12 ~ 9.13` 这类“结束日期不重复年份”的写法。
6. 前台来源后显示 `✓已核验`，方便区分“已人工交叉确认”和“纯自动抓取”。
